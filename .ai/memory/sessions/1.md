# Session 1

## ExamServer → personal-site conversion

- Deleted all exam content: `exams*/`, `exam-packs/`, `assets/` (exam
  images), `exam1.xml`, `exam2.xml`, plus the frontend's exam components,
  hooks, `src/api/`, and the `/login` and `/examsession` pages.
- Kept the Go backend packages (`pkg/`, `e2e/`, `signing/`, `scripts/`,
  `deployment/`) untouched for future dynamic features; only rewired
  `cmd/server/main.go` into a minimal server (embedded static export + API).
- Renamed the Go module `dcna-questions` → `personal-site` (go.mod + all
  imports; root package `dcnaquestions` → `personalsite`), the web app
  `web/exam-lab` → `web/site`, and the npm package to `personal-site`.
- Rebuilt the frontend as a personal site: Hero/About/Posts/Projects/
  Contact sections + footer, placeholder copy in the en/zh locale bundles.
  Preserved the dark-default theme, layout, TopBar, BreadcrumbNav,
  ProfileMenu, LanguageSwitcher, ColorModeToggle, and the i18n infra.
- ProfileMenu kept functional against `GET /api/profile`; GitHub icon comes
  from `@mui/icons-material/GitHub` (no custom SVG).
- Updated Dockerfile, .dockerignore, CI workflow, .gitignore, READMEs;
  fixed the stale `/examsession` case in `webfs_test.go`; reinstalled
  node_modules after the directory move dereferenced its symlinks.

## Dynamic blog data (`/api/dyn/`)

- `serverConfig.xsd`: new `<dynBlogData/>` section holding zero or more
  `<postMetadata/>` (id, href, title, description, lastModified, creation,
  tags), `<project/>` (id, name, description, url, tech), and
  `<authorContact/>` (id, kind, label, url) entries; ids required; dates are
  `xs:date`; `tech`/`tags` comma-separated. Example entries added to
  `serverConfig.xml` and `serverConfig.xml.example` (xmllint-validated).
- `pkg/models/dyn/dyn.go`: `DynBlogData`, `PostMetadata`, `Project`,
  `AuthorContact` types; `DynBlogDataProvider` interface;
  `FSBasedDynBlogData` — keeps only the config file path and re-reads and
  re-parses the XML on every call, so edits apply without a server restart
  (verified live: a new project appeared in the API with no restart).
- `pkg/api/dyn/dyn.go`: `DynamicBlogDataHandler` (implements http.Handler)
  routing the subtree internally: `GET /api/dyn/posts`,
  `/api/dyn/projects`, `/api/dyn/authorcontacts`; empty lists when
  unconfigured; errors as the standard `{"err": …}` shape.
- `pkg/api/dyn/healthz.go`: `HealthzHandler` moved out of main.go.
- main.go: re-added `--config-xml`; wired `/api/dyn/`; removed the
  hard-coded `handleContact` and `handleProfile`; `/api/profile` now served
  by `pkg/api/profile`'s ProfileHandler backed by the new
  `pkg/session.StaticVisitorSessionManager` (hard-coded "Visitor" identity
  until a login system exists).
- Dockerfile: `HEALTHCHECK` runs the binary's own `--healthz-probe` mode
  (the scratch runtime has no shell or curl); probe exit code verified both
  ways.

## Frontend dynamic wiring

- `src/hooks/useDynBlogData.ts`: `useDynPosts`, `useDynProjects`,
  `useDynAuthorContacts` (react-query), with wire types mirroring the API.
- Posts/Projects/Contact sections render from the API; static placeholder
  arrays removed from the locales; sections keyed by entry `id`.
- Post cards show a single date chip: outlined "Updated {date}" when
  `lastModified` differs from `creation`, otherwise the creation date
  (creation chip hidden for edited posts, per user request).
- Loading states use MUI `LinearProgress` (block-level) in all three
  sections; verified visually with Slow 3G throttling.
- Fixed the missing vertical gap between the Contact subtitle and the
  contact buttons (`mt: 2` on the Stack).

## Validation

- `go build ./...`, `go vet ./...`, and package tests (new tests for both
  dyn packages, the session manager, and healthz) all pass.
- `npm run build` + `npm run lint` clean.
- Browser-verified: dark/light themes, English/中文 switching, and the
  network log confirming `/api/dyn/*` responses drive the rendered cards.
