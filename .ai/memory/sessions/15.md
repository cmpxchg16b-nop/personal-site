# Session 15

Two deliverables: an SS type-coherence audit (frontend `types.ts` vs
backend `pkg/models/ss`), and the new Go negotiator package `pkg/rtc` —
the counterpart of the frontend `negotiate.ts` (RTCNegotiator /
PerfectNegotiator), built on pion/webrtc v4 with channel-based SS event
I/O. The audit found NO drift; the negotiator needed two
pion-specific adaptations that are the session's real findings.

## Type coherence audit: CLEAN

Every wire type in `web/site/src/api/ss/types.ts` has a field- and
JSON-key-identical Go mirror in `pkg/models/ss/ss.go`: the six opaque id
types, both well-known UUIDs, `EPAddr`, all seven `c2SEv` payloads and
the event itself, `ErrorCode` 1-5 in the same order, all seven `s2CEv`
payloads, `PingPongMsg` (TS `number` ↔ Go `uint64` — same JSON shape),
`ClientToClientEv` (`RTCSessionDescriptionInit` ↔
`webrtc.SessionDescription`, `RTCIceCandidateInit` ↔
`webrtc.ICECandidateInit` — pion marshals the exact browser shapes), and
the `SignallingEvent` envelope. TS-only extras `ChatUser`/`ChatChannel`
are UI view types, not wire types — deliberately not mirrored. No edits
were needed on either side.

## pkg/rtc design (mirroring negotiate.ts)

`pkg/rtc/negotiate.go`. `Negotiator` interface:
`Negotiate(ctx, ssEvIn <-chan *ss.SignallingEvent, ssEvOut chan<- *ss.SignallingEvent) error`
— the channel counterpart of negotiate()'s ReadableStream/WritableStream
pair; returns nil on input close, ctx.Err() on cancel,
ErrAlreadyNegotiating on double-run. `PerfectNegotiator` mirrors the
class: `Polite` = lexicographically smaller subscriber id,
`PerfectNegotiatorOptions{ChannelId, SelfSubscriber, PeerSubscriber}`,
constructor rejects self-negotiation (ErrSelfNegotiation) and nil pc
(ErrNilPeerConnection). Error sentinels are exported; per-event failures
are logged to options.Logger (slog, default slog.Default()) and
swallowed, mirroring the frontend's console.error catch-alls.

Concurrency: pion fires OnNegotiationNeeded/OnICECandidate on its own
goroutines, so the callbacks only funnel work (negotiation-needed /
candidate / nil-candidate end-of-candidates) into an internal buffered
channel consumed by the single Negotiate loop goroutine — the Go
rendition of the browser's event loop, so makingOffer/ignoreOffer/
isSettingRemoteAnswerPending need no mutex. Note those flags are
defensive-only here: the serialized loop makes them always-false at
decision time, kept for pattern fidelity. Outbound events mirror
sendToPeer exactly (From empty, To = well-known SS service id, fresh
uuid msgId, c2c addressing) and apply channel backpressure like
WritableStream.write().

## THE BIG ONE: pion cannot roll back — polite yield = pc rebuild

The browser's perfect negotiation relies on the polite peer's offer
being implicitly rolled back when a colliding offer arrives. Pion
v4.2.18 has SDPTypeRollback and setDescription branches for it, but
rollback is UNREACHABLE, verified empirically with a scratch probe:
bare `SetLocalDescription({Type: Rollback})` → InvalidModificationError
(the empty-SDP pre-check has no rollback case); rollback with a dummy
"v=0" → SDP parse EOF; rollback carrying the last offer's SDP →
"invalid proposed signaling state transition:
have-local-offer->SetLocal(rollback)->stable" — checkNextSignalingState
simply has no such transition. And from have-local-offer, SetRemote
accepts ONLY an answer — which the impolite peer (having ignored our
offer) never sends, so glare without rollback is a true deadlock.

Adaptation (documented in the package comment and the
NewPeerConnection option doc): the polite peer yields by REBUILDING its
peer connection — options.NewPeerConnection factory must return a fresh
pc with every track/data-channel/handler re-registered; the negotiator
closes the old one, attaches to the fresh one, and answers the colliding
offer on it. Glare candidates are not lost (they can only arrive after
the colliding offer, by which time the swap happened). Nil factory →
polite peer logs and ignores the offer like the impolite one (deadlock
until a side restarts) — fails soft, not wrong. Cost vs browser: a
connection reset when glare hits mid-session; unnoticeable during
initial establishment. This is the one behavioral deviation from
negotiate.ts; docs/signalling-server.md's c2c section states it.

## The constructor-attach race (why handlers attach in NewPerfectNegotiator)

Pion drops a negotiation-needed event fired while NO handler is
attached: its flag stays set and negotiationNeededOp aborts on the set
flag, so the event never re-fires until the next stable transition.
Attaching handlers in Negotiate() (my first cut) therefore loses every
pc change made between construction and loop start — caught by
-count=5 as a rare "state is new" stall. The browser re-fires the event
on the next task, so the frontend never sees this. Fix: attach in the
constructor; callers must construct the negotiator before any
negotiation-triggering pc change and start Negotiate promptly (buffered
funnel covers the gap).

## gotchas

- Callback closures must CAPTURE the done channel at attach time —
  reading the per-run-reassigned n.done field at fire time is a data
  race (caught by -race). Same for any field pion's goroutines could
  touch: the funnel channel itself is construction-stable and fine.
- Tests that park a pc in have-local-offer then run the negotiator must
  DRAIN the outbound channel: ICE gathering starts at
  SetLocalDescription and trickle events backpressure a full channel,
  wedging the loop before it reads the test's event (like the frontend's
  awaited writer.write()).
- Pion logs "dropping candidate with ufrag ..." at ERROR during glare —
  that's the ignored side's candidates being rejected, by design, from
  pion's own logger (not ours).
- `webrtc.ICECandidate.ToJSON()` (value receiver) gives the
  browser-shaped ICECandidateInit; nil candidate = end-of-candidates →
  send empty `ICECandidateInit{}` (mirrors the frontend exactly).
