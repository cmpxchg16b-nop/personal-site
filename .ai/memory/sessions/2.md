# Session 2

## Blog post layout & rendering

- `web/site/src/app/posts/layout.tsx` (was empty): the /posts layout — a
  centered 768px reading column inside the root layout's padded `<main>`
  (horizontal padding stays with `<main>`/TopBar so edges align). Vertical
  padding added per user request: `pt: { xs: 2, sm: 4 }`, `pb: { xs: 6,
sm: 8 }` — air under the top bar, and a generous bottom since post pages
  have no footer.
- `src/components/PostView.tsx` (new): the shared post shell. Renders the
  header from the post's `/api/dyn/posts` metadata looked up by `postId`
  (serverConfig.xml stays the single source of truth): title as h1, the
  same date/tag chip rule as the Posts cards (edited posts show only an
  outlined "Updated {date}" chip), and the description as a lead paragraph.
  LinearProgress while pending, warning Alert on error; the authored body
  renders regardless when metadata is missing/fails. Dates format via
  `localeTagFor(i18n.language)`, so the chrome localizes while post bodies
  stay authored content.
- `src/components/prose.tsx` (new): the post-authoring kit — H2/H3/H4, P,
  Link, Ul/Ol/Li, Code (inline chip), CodeBlock, Quote, Hr. Post bodies are
  native .tsx composition (per user: no plain HTML authoring), so an earlier
  descendant-selector (`proseSx`) design was discarded. The kit is a client
  module because `Link` passes `NextLink` as a `component` prop, which
  cannot cross the server/client boundary (hit the exact runtime error
  "Functions cannot be passed directly to Client Components" before the
  fix). Internal hrefs route through Next.js; absolute http(s) links open in
  a new tab — the same rule as the cards' Read button.
- `BreadcrumbNav.tsx`: new `/posts/*` case — Home > Posts (links to
  `/#posts`, there is no standalone posts page) > raw slug (the title lives
  in server config, fetched by the page, not available to the bar).

## Design iterations (user feedback)

- Code block radius: sx numeric `borderRadius` is multiplied by the theme's
  `shape.borderRadius` (12px), so `borderRadius: 2` rendered a very round
  24px. Set explicit px: CodeBlock `4px`, inline Code `6px`.
- `fontWeight` moved from the Typography prop into `sx` (prose.tsx H2/H3/H4,
  PostView title).
- "Text too heavy": verified computed styles in the browser (h1 700,
  h2/h3 600, body 400), then reduced headings 600 → 500 and title 700 → 600. The user then hand-set the title to 500 — title and headings are now
  all 500, hierarchy carried by size alone. Body stays 400.

## Responsive Source button (Projects section)

- `ProjectsSection.tsx`: the card's Source button collapsed awkwardly on
  narrow viewports. It now hides its label below `sm` (600px) and renders as
  a centered icon-only contained button: the label sits in a span with
  `display: { xs: "none", sm: "inline" }`, the startIcon's text-gap margins
  are neutralized at xs (`ml`/`mr` 0, restoring `-4px`/`8px` at sm), and
  `minWidth` drops to 0 at xs (64px default at sm). `aria-label` keeps the
  button named while the visible text is display:none.
- Verified at 390px (icon-only, centered) and 1280px (icon + text,
  unchanged); lint clean. The Posts cards' Read button has the same pattern
  but a short label that still fits — left as-is, offered as a follow-up.
