# Session 25

The deliverable: a unified audio source model (`pkg/models/audiosource`)
for the music bot — songs become DATA (the configuration document's
`<audioSource/>` entries under `<musicBot/>`) instead of program source —
plus the music bot rework that follows from it: a streaming player whose
track codec follows the song, a one-off synthesizer for the shipped
chiptune asset, the XSD/example/wiring, and the docs.

## The model (pkg/models/audiosource)

`AudioSourceData` mirrors the spec: Id, dns-label Name, Description,
Author, SampleFormatType (linear_pcm|mu_law), BitDepth (8|16|32),
NumericType (unsigned|signed|float), NumChannels, Interleaved (must be
true), InlineData ([]byte), URL (http(s) or path; inline takes
precedence), Compression (none|flac), SampleRate, NumTotalSamples
(inter-channel definition — NOT ×channels; **0 denotes a streaming
source** of unknown length). Two combinations accepted: linear_pcm
48000/2ch, mu_law 8000/1ch. Validate() is wiring-time; loading is lazy.

**The sample data is a stream, never a `[]byte`** (user directive): each
`Open(ctx)` returns a fresh `Stream` — io.ReadCloser + `Rewind(ctx)` +
`Format()`. Three raw kinds back it: inline (bytes.Reader), file
(os.File), http (re-GET on rewind). Uncompressed streams pass bytes
through with an end-of-data count check against NumTotalSamples (when
known); FLAC streams decode on demand (mewkiz/flac, `flac.New` +
ParseNext; frames interleave to LE), with **the file header's stream
info taking precedence** — it lands on the stream's `Format()`, not on
the struct, and the effective combination must still be supported
(24-bit or 44.1 kHz FLAC → Open error). **No mutexes anywhere** (user
directive): Open is stateless per call; sources are shared by pointer
and need no synchronization.

**Rewind is smart** (user directive): local files and inline data SEEK
back to their first byte (no close/reopen); only http re-fetches. The
music bot loops its songs indefinitely on this.

## The player rework (musicbot)

- **The codec follows the song — nothing is downmixed unless it must
  be** (user directive, correcting an initial plan that decimated 48 kHz
  stereo into 8 kHz mono μ-law): a μ-law song rides a **PCMU track**,
  bytes becoming the RTP payload verbatim; a linear PCM song rides an
  **opus track (48000/2)**, samples normalized to interleaved s16
  stereo (s16 is a bit-exact fast path; u8/u16/s32/f32 normalize
  through [-1,1]) and encoded 20 ms at a time with libopus
  (github.com/hraban/opus, cgo) at 96 kbit/s. Both codecs are in
  pion's default media engine.
- The player is an **actor**: the pump goroutine alone owns the open
  stream, the normalizer and the encoder; a same-family mid-call switch
  travels as a request on a `switches` channel and is applied between
  frames (open-new-first, so a failed switch keeps the old song
  playing). No mutex; `sync.Once` stop as before.
- **A cross-family switch replaces the whole player** (the track's codec
  is fixed at creation): attach the new track before detaching the old,
  so the music never leaves the wire; while still ringing, just swap.
- `readLooping` reads frame-sized buffers with rewind-on-EOF looping;
  the empty-source guard needed a `stalled` flag — a fill that starts
  exactly at the stream's end (the previous fill consumed it to the
  last byte without meeting EOF) rewinds once too; only two consecutive
  zero-progress EOFs are "holds no samples". Caught by the wire suite's
  looping test.
- Empty songbook: a voice INVITE is left unanswered (warn log); /play
  answers the unknown-song hint. Sources injected via
  `Configuration.AudioSources` (validated at wiring; duplicate name
  panics, mirroring the duplicate-label precedent).

## cgo consequences

The opus encoder lives behind the implicit `cgo` build tag
(opus_encoder.go / opus_encoder_stub.go): a cgo build gets libopus; a
pure-Go build (the CI binary matrix's cross-compiles, the scratch
Docker image — both CGO_ENABLED=0) compiles a stub whose music bot
plays μ-law songs and reports the limitation for linear PCM ones
(errNoOpus at track preparation). The CI test job now apt-installs
libopus-dev + pkg-config so the tests exercise the real encoder.
pion/opus v0.1.0 turned out to be decoder-only (its encoder is
internal/); it was dropped from go.mod in favor of hraban/opus.

## Wiring, config, asset

- XSD: `musicBotType` extends `botClientType` with `audioSource*`;
  `audioSourceType` is simpleContent over base64Binary (the inline
  data) with enum-typed attributes (sampleFormatType, bitDepth,
  numericType, compression) and numTotalSamples as nonNegativeInteger
  (0 = streaming). serverconfig.go: `MusicBotXML` (embedded
  BotClientXML — encoding/xml flattens the attributes, proven by test)
  - `AudioSourceXML.AudioSourceData(configDir)` (base64 text decode
    with whitespace stripping, compression/interleaved defaults, relative
    url joined against the config document's directory, Validate).
- main.go: startMusicBot converts the entries (an invalid one fails
  startup) and injects them; sample data still loads lazily.
- `cmd/synthchiptune` renders the old song.go composition
  (self-contained copy — the composition left the bot) to
  `assets/chiptune.ulaw`: 128000 bytes, sha256
  f29b31ba5c1b5a93d71cc08ae7c3a35196ad003be41b62bd8a6cc6eafccc0057,
  byte-deterministic. The example and the local serverConfig.xml point
  at it.

## Tests

- audiosource: Validate table; inline/file/http streaming; rewind
  (inline+file seek, http re-fetch counted); inline precedence over
  url; independent Opens; end-of-data count mismatch error; streaming
  NumTotalSamples=0; FLAC roundtrip + header precedence (declared 999
  vs header 300) + streaming header (NSamples 0) + unsupported
  effective combination — FLAC vectors encoded in-test with mewkiz's
  encoder (mind the 16-sample flac block-size minimum).
- musicbot wire suite: injected songbook (chiptune μ-law + "stereo"
  linear PCM + "flac" songs); new tests: linear PCM plays as opus
  (codec + clock rate + non-empty packets), FLAC plays as opus,
  cross-family mid-call switch (PCMU track succeeded by an opus
  track), a 2-frame song loops (six 160-byte packets = three loops),
  empty songbook. opus tests `requiresOpus`-skip in no-cgo builds.
- player units: readLooping (wrap/straddle/empty), sampleToInt16
  table (mind: u8 max → 32511 and s16 max → 32766 — the [-1,1]
  normalization is not endpoint-exact; the s16 fast path IS exact),
  stereoNormalizer (s16 identity, u8 bias), setSource lifecycle.
- serverconfig: attribute flattening, base64 chardata with line wraps,
  defaults, url resolution matrix, conversion validates.
- synthchiptune: shape/determinism/mismatched-voices panic (ported
  from song_test.go) plus the μ-law codec vectors — the encoder's only
  home after the rework (musicbot's mulaw.go was dead code on the
  playing path — the PCMU path passes bytes through, the opus path
  uses libopus — so it was deleted with its tests, which moved here,
  to where the code lives).
