# Session 3

## Short-link feature (server-side)

- `pkg/models/shortlink/shortlink.go` (new): the `ShortLinkDataProvider`
  interface — `GetShortLinkById(ctx context.Context, shortLinkId string)
(string, error)` returning the destination href — plus the
  `ErrShortLinkNotFound` sentinel (matched with errors.Is, drives 404 vs
  500 in the handler) and `FsShortLinkDataProvider`. The FS provider keeps
  only the serverConfig.xml path and re-reads/re-parses per call, the same
  live-edit pattern as `FSBasedDynBlogData`; it mirrors only the
  `<shortlink/>` entries of `<dynBlogData/>` (xml.Unmarshal ignores the
  rest). ctx is part of the interface for future remote-backed providers;
  the FS one ignores it.
- `pkg/api/links/links.go` (new): `ShortLinkHandler` (http.Handler) with an
  internal ServeMux routing `GET /links/{id}` → 302 redirect. 302 not 301,
  deliberately: the mapping is live-editable and browsers cache permanent
  redirects. Unknown id / nil provider → 404; provider error → 500 JSON
  (`pkg/utils.ErrorResponse`), mirroring pkg/api/dyn. `/links/` with no id
  and non-GET fall out of the ServeMux patterns (404 / 405) for free.
- `cmd/server/main.go`: mounted at `/links/` (no /api prefix — the paths
  are meant to be shared), unconditionally like `/api/dyn/`; with no
  `--config-xml` every id 404s.
- Schema/config: `shortlinkType` (required `id` + `href`, both xs:string)
  added to serverConfig.xsd as the last child of the `dynBlogDataType`
  sequence (order matters in xsd:sequence: postMetadata*, project*,
  authorContact*, shortlink*). Three placeholder entries in
  serverConfig.xml (`gh`, `first-post`, `posts`), two in
  serverConfig.xml.example; both validate via xmllint.
