# Request

全面调查 WebRTC 子系统在 Wi-Fi 切换等断线后永久停留于 ICE `disconnected`、
但刷新页面即可恢复的问题。用户明确要求排除“网络本身/STUN 不可用”这类未证实假设，
重点检查是否根本没有触发重连、重试策略是否失效，以及历史状态机和技术债设计。
调查、修复、测试与审核均在本任务内完成。

# Investigation

## 已确认的事实

- 浏览器和 Go 的 ICE watchdog 都没有次数上限，且会在 `checking` / `disconnected`
  中继续调度；“代码完全没有 timer”不是事实。默认 disconnected 宽限 3s，随后指数
  退避，标称上限 30s，±20% jitter。
- 真正的死状态是重试没有重试实际 SDP 协商。polite 端首份 restart offer 或其 answer
  丢失后停在 `have-local-offer`。浏览器后续只调用 `restartIce()`，这不保证再次发出
  `negotiationneeded`；Go 后续 `makeOffer` 又被非 stable guard 直接拒绝。两端都没有
  在 watchdog 中重发当前 local offer。
- 浏览器已有 `retransmitPendingOffer()`，但唯一调用点是本端 proxy 更换。对端 roaming、
  answer 丢失、或本端最后一次 proxy 更换之后丢包都不会触发它。现有 mock 却在每次
  `restartIce()` 时无条件制造 negotiationneeded，恰好掩盖真实死状态。
- SS 没有端到端 SDP 送达确认；`ws.send` / Go channel send 成功不代表对端收到。目标
  注册尚未恢复时 SS 会拒绝 relay，旧 socket 也可能接受写后丢消息。因此不能假设第一份
  offer 一定送达，重传属于恢复状态机的必要部分，不是多余双写。
- Go `WebSocketSignallingTransport` 写失败只退出写协程，不关闭连接，也没有 read
  deadline 或 ping/pong；读协程可在半开 TCP 中永久阻塞，外层 bot 的无限 reconnect
  循环因此永远得不到执行机会。
- Go keepalive 已收到 `SubscriberNotFound` 时仅记录日志，不结束失效 Run 或重新注册。
  协议注释明确要求此时 re-register。
- Go 每次 Run 会重建 PC，而浏览器同 ID roaming 保留 PC。这是不一致的历史设计，但
  不必先做大拆：保留旧 PC 的一端持续 restart request / pending-offer retransmission
  可以把新 PC 拉入协商。先用回归证明闭环，再决定是否仍需生命周期重构。

以上分别来自 `web/site/src/api/ss/{ice_restart,negotiate,peersessions}.ts(x)`、
`pkg/rtc/{negotiate,transport,client}.go`、`pkg/models/ss/ss.go` 及现有测试的直接阅读；
两个独立只读调查得到一致主根因。尚未做物理 Wi-Fi 实验，因此不能把现场限定为单一
丢包点，但上述每条永久失效路径都可由代码或故障注入确定。

# Plan

目标行为：ICE 曾可用后进入 disconnected/failed 时，在 session 未显式关闭的前提下无限
恢复；每次有间隔的重试必须推进实际协商，而不只是调用一个可能已经无效的 API。polite
端独占自动 restart-offer 所有权，impolite 端继续发 request，避免双方同时制造新 offer。

1. 先添加并运行失败回归：浏览器在 `have-local-offer` 且 `restartIce()` 不再发出
   negotiationneeded 时，下一轮 watchdog 与远端 restart request 都必须重发当前 offer；
   Go 在首份 offer 未答时也必须重发，并区分普通 pending offer 与已含 ICE restart 的
   offer，避免 answer 后多余地再 restart。
2. 浏览器把 pending-offer retransmission 纳入每次 ICE watchdog 和 polite restart-request
   处理；保留现有 proxy 更换重传、pending-write 去重、成功取消和 teardown。
3. Go 在 ICE 恢复路径重发当前 local offer，跟踪当前 local offer 是否已请求 ICE restart。
   普通 offer 答完后仍执行已 latch 的 restart；restart offer 的重传则不错误制造第二轮。
4. Go transport 由同一写协程发 WebSocket ping，pong 续 read deadline；任何写/ping 失败
   立即关闭连接并向 Run 返回错误，唤醒读侧，使现有 bot reconnect loop 真正执行。
5. Go client 关联 keepalive msgId；其 `SubscriberNotFound` / `ChannelNotFound` 回复终止
   当前 Run 并交给外层间隔重连重新注册，不能把发往其他已离开 subscriber 的 c2c 错误
   误判为本端 membership 丢失。
6. 增加真实 pion 的丢首份 offer/answer 协商回归、WebSocket 半开写失败和 pong timeout/
   healthy-pong 测试，以及 keepalive 失效与无关 c2c 错误控制测试。更新重连文档。
7. 运行聚焦测试、相关重复/race 测试、完整 Go/Web 检查、独立代码审核；把实际结果、
   设计修正、未做的物理网络验证和剩余风险写回本记录。

# Final outcome

## 根因与修复

1. **原实现不是完全没有 timer，而是 timer 空转。** 首份 offer/answer 丢失后，
   polite PC 停在 `have-local-offer`；浏览器反复 `restartIce()` 不保证产生新
   negotiationneeded，Go `makeOffer` 又被 stable guard 拒绝。现在浏览器和 Go 的
   ICE watchdog 都重传当前 pending local offer，polite 收到 restart request 时也重传。
   重复 offer 会让对端重新 answer；重传读取最新 LocalDescription，允许新增 candidates。
2. **impolite 与普通/ICE-restart offer 状态。** Go impolite watchdog 同时发送 request
   和自己的 pending offer；`iceLocalOfferRestart` 区分普通 offer（answer 后仍需 restart）
   与 restart offer（answer 后不制造多余第二轮）。普通与持续 glare 采用 2s delayed retry，
   stable/closed/teardown 取消，避免立即 duplicate 导致 polite 反复 rollback/rebuild。
3. **Go 信令半开连接。** `pkg/rtc/transport.go` 每 1s 发 WS ping，pong 续 3s read
   deadline；应用写或 ping 失败立即 close，唤醒 ReadMessage 并返回原写错误，让既有
   bot reconnectInterval 循环真正执行。新增真实 WS 半开写失败、缺 pong、健康 pong 测试。
4. **注册失效。** `pkg/rtc/client.go` 的 keepalive 使用 `keepalive:<run-uuid>:` 前缀；
   当前 Run 的 SubscriberNotFound/ChannelNotFound 不管延迟多久都会终止 Run 并重新
   注册，普通 c2c 目标离开和旧 Run 错误不会误杀。没有有限 history 或增长 map。

主要文件：`web/site/src/api/ss/negotiate.ts`、`pkg/rtc/negotiate.go`、
`pkg/rtc/transport.go`、`pkg/rtc/client.go`。回归位于对应 `*_test.go`、
`negotiate.test.ts` 和新增 `pkg/rtc/transport_test.go`；行为与计时已更新到
`docs/webrtc-reconnect.md`。Go bot 跨 Run 重建 PC 的既有生命周期未伪装成浏览器媒体
保留；旧 PC 侧的持续 request/retransmission 可与新 PC 重新完成协商。
