# Request

# Investigation

已知错误直接指向 SDP 协商约束：Firefox 收到的 remote description 改动了 `ice-ufrag` 或 `ice-pwd`，但它所对应的本地 offer 并未请求 ICE restart。需要核实这是 answer 对新 PC 身份的错误复用、glare/rollback 后描述配对错乱，还是重传/信令路由把不同代次的 SDP 混在一起；目前不预设根因。

# Outcome

## 根因与补丁

- 直接代码证据和公开 API 复现确认：Go polite 端在 glare 时通过 `NewPeerConnection` 换新 PC，再以新的 ICE/DTLS 身份回答 Firefox 之前的普通 offer。Firefox 因 answer 改动 `ice-ufrag`／`ice-pwd`、而本地 offer 未请求 ICE restart 拒绝该 SDP，后续状态停在 disconnected。
- 按用户要求新增 `third_party/webrtc` 子模块，基于 upstream `a497859f4f94` 创建 `fix/perfect-negotiation-rollback` 分支；主项目 `go.mod` 以 `replace github.com/pion/webrtc/v4 => ./third_party/webrtc` 使用补丁，require 基线更新为 v4.2.27，依赖由 tidy 同步。
- Pion `peerconnection.go` 新增 local/remote rollback 入口，空 SDP 不再提前拒绝；`signalingstate.go` 支持 `have-local-offer`／`have-remote-offer → stable`。只清对应 pending description，保留 stable current descriptions。
- 对 ICE restart offer 的 rollback 同时恢复 stable local/remote ICE 凭据并重新 gathering；否则同一 PC 随后的普通 answer 仍会携带新凭据。`icetransport.go` 增加显式凭据恢复路径，普通 restart 行为保持不变。
- 主项目 `pkg/rtc/negotiate.go` 的 polite glare 改为在原 PC 上 `SetLocalDescription(SDPTypeRollback)` 后回答，不再重建。`pkg/rtc/client.go` 删除 negotiator 重建工厂、hub rebuild note 及轨道/DataChannel 重建设施；初始 PC 自定义工厂仍保留。
- 主要回归：`third_party/webrtc/peerconnection_renegotiation_test.go` 覆盖双向 local/remote、普通与 ICE-restart rollback、stable descriptions 和真实 ICE/DTLS 重连；`pkg/rtc/negotiate_test.go` 要求原 PC 不关闭、对象不变；`pkg/rtc/client_test.go` 要求 DataChannel handler 不再因重建调用两次。相关媒体测试继续验证轨道与 codec pin。

## 中间失败与修正

- 首次 Pion 公开 API 回归实际失败：`InvalidModificationError: invalid SDP type supplied to SetLocalDescription(): rollback`。
- 首次主项目回归实际失败：日志仍走 `glare, rebuilding the peer connection`，原 PC signaling state 为 closed；改 rollback 后通过。
- 初版测试对整段 SDP 做精确比较，因 candidates 合法变化失败；改为 stable type 与 local/remote ICE 凭据断言，没有放宽身份要求。
- 初版真实重连测试未交换 rollback 后重新 gathering 的 candidates，且事件 helper 错过已发生状态；补全 candidates 并改为轮询当前 `ConnectionState` 后通过。
- 扩展 remote ICE-restart rollback 时复用了已 rollback 的旧 offer，导致 `stable->SetRemote(answer)->stable`；按真实协商改为重新创建 ordinary offer，最终连续 5 次通过。
- 首次 `go mod tidy` 遇到 sum.golang.org 连接超时；使用已下载模块缓存以 `GOSUMDB=off go mod tidy` 完成同步，后续全部测试和 vet 正常。
