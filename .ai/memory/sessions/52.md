- 部署后刷新 Firefox 页面，使用同一访客会话打开 `music-bot`，发送 `/play trancepulsefm`，接听并授权麦克风。测试结束后已点击 End the call，并确认重新出现 Start a voice call。
- 换网前基线曾出现一次短暂 `Disconnected`：日志从 `2026-11-21T16:06:34.091Z` 的 disconnected 到 `16:06:38.447Z` 的 connected，约 4.4 秒恢复。
- 自动切换到另一已知 Wi-Fi 的第一次后台点击无效果；调用系统“连接”动作后系统报告未能加入。随后由用户手动完成实际换网；未记录网络名称。
- 手动换网后，music-bot UI 持续 `Disconnected` 数分钟，远端音频频谱变平，不能判定为恢复。
- Firefox 控制台未再出现此前的 `Remote description indicates ICE restart but offer did not request ICE restart`／ICE 凭据不匹配错误。这是原报错路径的改善证据，但不是整体恢复成功。
- `about:webrtc` 记录到 11 次 ICE restart、0 次 ICE rollback；存在 `succeeded / nominated=true / selected=true` 的候选对，但接收带宽为 0。两次读取的 RTP 数值相同（inbound 5,947 packets、outbound 5,328 packets）；后台 Refresh 的效果未被工具确认，因此该相同计数只作辅助证据，不单独据此声称完成了可靠刷新。UI 长时不恢复、接收带宽 0 和频谱停止已足以判定本次复测失败。
- 服务端在换网时段先报告 ICE disconnected 并多次调度 restart，`16:08:10` 至 `16:08:12` 曾报告 ICE recovered，但之后仍持续发送 ICE restart offer，未形成稳定恢复。
