# Request

为 WebRTC 信令数据模型的频道和频道成员增加 `visible` 属性：成员注册时提供，后续对同一订阅的新注册可修改；`main` 频道固定可见。频道与成员列举排除不可见项，但信令寻址和 relay 仍可达。Web UA 默认可见并提供“在线/隐身”切换，选择必须持久化到浏览器本地且刷新后保留；Go Bot UA 默认可见且可配置。同步更新 Web、Go、操作逻辑、测试与文档，必要时本地构建并用浏览器检查 UI。

# Scope and status

Status: in progress. 覆盖信令协议与内存 provider、Go headless RTC client 和 Bot XML 配置、React 注册与刷新、可见性切换 UI、相关测试和文档。不修改无关功能，不提交或部署。

# Initial context

- 当前工作树在任务开始时干净。
- `/chat` 使用 `/api/ss/ws`；`useSignalling` 注册到 main，并每 5 秒查询频道、频道资料、成员和成员资料。
- Go `SimpleOnMemorySSProvider` 当前只有 main 频道，注册与订阅状态保存在进程内存中。
- Go Bot 经 `RTCClientConfiguration` / `BotClientXML` 注册；需要确认所有配置、schema、示例与测试的同步点。

# Investigation

- Go 重复注册同一 `(userId,userSessionId,channelId,subscriberId)` 当前会刷新 `lastActive` 并可更新 username，适合在同一入口更新 visible；空 subscriber ID 仍是新 incarnation。
- `listChannels` / `listChannelMembers` 是公共发现边界；`userProfileQuery`、`channelProfileQuery` 和 c2c relay 可直接按已知 ID 工作，过滤不应把这些路径一并禁用。
- Go client 在每次 `Run` 注册，XML 只在进程启动时读取；同一个活跃 Run 没有独立的运行时配置更新 API。Bot 的 visible 因而是启动配置，重连沿用。
- Go client 与 Web PeerSessions 都按公共成员列表增删 peer session。成员隐身后，其他客户端会在后续 listing 中将其视为离开；需求中的“信令仍可达”按 provider 的直接 c2c 路由保证，不擅自改变现有 peer reconciliation。
- Web 顶栏已有 `TopBarActions` portal，可让可见性控件与通话音量共存。`ChatUser.online` 表示在线/连接语义，不能复用为公共可见性。
- Web 注册 effect 可在 visible 改变时用同一 proxy、同一 subscriber ID 重跑；应保持已确认身份/列表和 `registrationReady`，避免误重置 peer 会话。控件在切换确认前禁用，避免并发重注册。
- 为兼容旧客户端并区分“未指定”和显式 false，Go register wire 字段采用 `*bool`（nil 默认 true），TS 为可选 boolean；profile 中则始终返回具体 bool。Go XML 沿用 raw string + `strconv.ParseBool` 的默认处理风格，RTC 配置用 nil 默认 true 的 `*bool`。

# Plan

1. Go 信令模型：为 register/profile/channelProfile 和内部 subscriber/channel 状态增加 visible；main 固定 true；重复注册更新 visible；公共列表跳过不可见频道和成员，不可见频道的公共成员列表返回空最终页；直接 profile 查询与 relay 保持可用。增加默认、双向切换、过滤、分页及信令可达测试。
2. Go client/Bot：`RTCClientConfiguration.Visible *bool` nil 默认 true，所有注册/重试/重连携带有效值；`BotClientXML.Visible` 默认 true、显式 false 和非法值解析，接入 `startBotClient`；同步 XSD、示例和文档。
3. Web 协议和列表模型：注册显式携带 visible，profile 模型与 `ChatChannel`/`ChatUser` 同步；刷新逻辑保留服务端过滤语义。
4. Web 状态与 UI：新增本地存储 helper，使用固定 key 保存 true/false，损坏/不可用存储回退 true。首屏 effect 先读取偏好再允许注册；切换和漫游重连沿用偏好。`TopBarActions` 中新增在线/隐身控件，切换触发同 ID 重注册，pending/未注册时禁用，中英文文案同步。
5. 测试：覆盖本地存储读写与异常、首次注册不抢先使用默认值、在线→隐身→在线同 ID 重注册、重连保持隐身、PC 不因重注册本身重置；Go provider、client、XML 和必要的真实 WS e2e。
6. 运行 gofmt、聚焦 Go 测试与 race、Web Vitest/lint/build 和 Go build；可行时本地启动并用浏览器检查默认、切换、刷新持久化和列表隐藏。
7. 回写改动、验证命令、审查/修正和剩余风险。

## 边界与剩余风险

- 隐身是公共目录过滤，不是访问控制；已知地址的直接 profile/c2c 可达。现有 Web/Go peer reconciliation 会在成员从列表消失后拆除对应 peer session，恢复可见后重建；未扩展成“隐身但保持通话”。
- 当前只有 main 频道，故不可见频道行为由 provider 单测覆盖，真实 WS e2e 覆盖成员过滤、更新、回执和直接 relay。
- localStorage 不可用或损坏时按需求默认 Online；混合旧 SS 无法提供隐身，Web 回退 Online，Go Bot 明确报错。
- 审查中一次更宽的 `pkg/rtc` race 运行命中未修改 ICE 重启路径的 third_party/webrtc 竞争；本次可见性相关 race 聚焦测试通过，未处理该无关既有风险。
