# 请求

继续优化 WebRTC 子系统 Web 端，参考 Telegram 风格重做左侧边栏：

- Chat Tab：保留当前会话列表，使用聊天图标。
- Phone Tab：展示通话记录并支持新建 SIP 呼叫；点击记录也可呼叫。内容区右下方提供加号按钮，弹出“请输入被叫号码”对话框，包含号码输入、取消、呼叫。取消或呼叫均关闭；呼叫提示“暂未实现，敬请期待”。
- Settings Tab：展示只读用户名和头像；包含“SIP 注册”入口，点击后右侧原消息区切换为 SIP 注册设置页，展示注册状态，并提供添加 SIP 服务器、用户名、密码、连接方式等纯前端占位交互。

本次为后续扩展铺垫，不接未实现的 SIP 服务端能力。

# 调查结论

- 当前入口为 `web/site/src/app/chat/page.tsx`，业务状态集中在此；`ChatApp` 是受控布局组件，`ChatSidebar` 只保存搜索与频道展开状态，右侧为 `ConversationView`。
- 左侧现状已用 Firefox MCP 在 `http://localhost:8080/chat` 实测：生产静态导出由本地 Go 服务提供，访客登录后为搜索框 + main 频道树 + 右侧会话占位。
- 基线复现沿用上次：`npm run build` 生成 `web/site/out`，`go build` 后以 `JWT_SECRET=... server serve --addr=127.0.0.1:8080 --config-xml=serverConfig.xml` 启动。后续按用户要求改用 `web/site` 的 Next dev server（3000），由 `next.config.ts` 将 `/api` 转发到 8080，避免界面调整时反复重建静态导出。
- 现有 `messages` 中 `phone-call` 项就是真实 WebRTC 通话历史，包含方向、媒体类型、状态和时间；`onStartCall(ref, kind)` 可直接回拨。新 SIP 拨号没有服务端实现，应独立走占位提示，不能复用后伪装成真实 SIP 呼叫。
- 当前用户资料可由 `users[currentUserId]` 获得，`UserAvatar` 已提供稳定头像；无需新增资料接口。
- 项目没有 DOM 组件测试设施，现有 Vitest 主要测试协议/hooks；本次以 TypeScript、ESLint、生产构建和 Firefox 交互回归为主，如提取纯通话历史逻辑则补对应单元测试。

# 计划

1. 在左侧栏增加 Telegram 式 Tab 导航：Chat/聊天图标、Phone/电话图标、Settings/设置图标；原搜索与频道树完整保留在 Chat 内容区。初版采用窄纵向导航，用户反馈后修正为侧栏底部横向三项导航，内容区占满上方宽度。
2. Phone 内容区从现有 `messages` 派生按时间倒序的通话记录，显示联系人、方向/状态和相对时间；支持按 display name、user id、subscriber id 做不区分大小写的包含搜索。后续需求取代初版“点击直接回拨”：点击记录在右侧显示 Linphone 式联系人详情，视频、语音、短信三个操作均为未实现占位。
3. Phone 内容区内部右下角放置加号 FAB；弹出“请输入被叫号码”对话框，提供输入、取消和呼叫。空号码禁用呼叫；取消或呼叫关闭，呼叫后用 Snackbar 提示“暂未实现，敬请期待”（英文资源同步），不发送网络请求。
4. Settings 内容区显示只读头像、用户名及“SIP 注册”入口。Tab/右栏状态由 `ChatApp` 管理：点击 SIP 注册后右侧切换为设置页，切回 Chat/Phone 或选择会话时恢复会话区。
5. SIP 注册页显示“未注册”状态和纯前端说明；提供 SIP 服务器、用户名、密码、UDP/TCP/TLS/WebSocket 连接方式及添加按钮。添加仅更新页面内配置列表，不展示密码、不持久化敏感信息、不发请求。
6. 保持桌面双栏和移动端列表/右栏切换；SIP 设置页和联系人详情提供移动端返回。底部导航最终为无文字、20px 图标、44px 高度。通话记录使用淡分割线、透明默认背景、轻微 hover/选中高亮，记录与详情头像均不显示在线状态灯。补充中英文资源与必要测试。
7. 运行聚焦检查、全量 Vitest、ESLint、TypeScript/Next 生产构建；使用 Firefox + Chrome 双访客制造真实通话历史，验证搜索、联系人详情及占位动作、拨号弹窗两种关闭路径、提示、只读资料、SIP 表单添加和移动端布局。
8. 回写实际改动、验证命令、截图/交互结果及剩余限制；不提交、不部署。

# 执行记录与需求修正

- 初版纵向图标栏经反馈改为底部横向三图标；文字标签移除，仅保留无障碍名称。导航尺寸最终为 44px 高、20px 图标。
- Phone 顶部标题/副标题删除，只保留姓名或号码搜索；记录右侧电话图标删除。选中态按 message id 而非联系人区分，避免同一联系人多行同时高亮。
- 通话记录点击行为由初版真实 WebRTC 回拨改为联系人详情；详情视频/语音/SMS 都显示“暂未实现，敬请期待”。既有 Chat 会话头部的真实音视频呼叫不变。
- 记录默认计算背景为 `rgba(0,0,0,0)`，条目间为 `rgba(255,255,255,0.12)` 1px 线，hover 与选中均为 `rgba(255,255,255,0.08)`；末条无分割线。记录小头像和详情大头像均去掉 presence 指示灯。
- Settings 的资料只读说明、SIP 入口辅助说明和资料区底部分隔线按反馈移除。
- 一次独立审查调用被后续新需求打断，未形成审查结论；最终以静态检查、双浏览器实际交互和计算样式检查复核。

## 限制与后续

- 当前信令模型没有独立被叫 SIP 号码字段，号码搜索覆盖 `user.id` 与 `subscriberId`；接入真实 SIP 历史后应增加并搜索专用号码字段。
- SIP 注册和配置仅为组件内 placeholder，离开页面后丢失，不持久化、不请求服务端，也不代表真实注册成功。
- 通话历史沿用现有内存消息模型，刷新后的持久化不在本次范围内。
- 本次未修改 Go 代码；未新增 DOM 组件测试设施，交互由纯函数单测与浏览器实测覆盖。
