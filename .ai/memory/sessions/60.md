# 请求

将 `/chat` → Settings → SIP Registration 的前端占位页接入系统级 SIP 注册能力：

- 服务端是用户 SIP credential 与注册状态的单一权威来源；当前仅内存保存，后续可考虑 credential 持久化。
- credential 按用户隔离，可添加、编辑、删除和切换 enabled；enabled 后自动注册，禁用/启用或编辑触发正确的重注册生命周期，失败自动重试。
- 服务端维护每个 credential 的注册状态，前端从 API 获取并展示；不将注册状态存入 localStorage。
- 维护 SIP URI/AOR 到用户 ID 的关联；收到找不到用户的 SIP 信令时记录日志。
- 新增 `docs/` 设计文档，长期追踪用户级 SIP 信令、呼叫、媒体能力的设计、进展、问题和决策。
- 启动 `localhost:3000` Next dev server，实际调试 UI。

当前状态：方案已写入，准备实现。工作区基线干净；上一编号开发记录为 59，本次使用 60。

# 调查结论

- 占位 UI 为 `web/site/src/components/chat/SipRegistrationSettings.tsx`，credential 仅存组件 state，离开即丢失；项目已有 React Query 与 JWT cookie 数据获取模式。
- 动态 API 在 `cmd/server/main.go` 注册，非白名单路径统一经 JWT 与 session middleware；可信 owner 必须取 `Session.SubjectId()`（JWT `sub`），不能用 username、session id 或请求体 user id。
- `pkg/rtc/sipbot` 的 account 生命周期绑定 bot/WebRTC 会话，不刷新注册，不是系统服务的权威状态；不能简单复用其内存 store 或把浏览器接到 PBX。
- vendored diago 提供 `RegisterTransaction.Register/Qualify/Unregister`，但同一 transaction 非并发安全；刷新、失败重试与注销必须由新 worker 串行驱动。其缺省 REGISTER transport 为 UDP，其他 transport 必须写入 Request-URI 参数。
- diago 当前不暴露已授予租期，且只读响应顶层 `Expires`，不读常见的 `Contact;expires=`。为正确刷新需要一个小而明确的 vendored patch，并在 nested module 单测。
- 浏览器仅调用本站 API/SS；SIP 由 Go 服务端发起和终结。未来入站路由是 AOR → JWT user id → `websocket_ss` CAM 中该用户的全部活动 UA，不是 SIP over WS 到浏览器。本期不实现振铃、呼叫或媒体代理。
- 媒体长期原则（用户补充）：代理只重写传输与 SDP 必要地址/安全属性，保留双方真实 codec 能力；WebRTC 侧 DTLS-SRTP 与 SIP 侧常见明文 RTP 在 RTP 安全层转换，不转码、不虚构或预设浏览器能力。

# 实现计划

1. 新增 `pkg/sipregistration` 领域与运行时：按 owner/id 存 credential，密码仅内部保存；规范化并全局唯一索引 AOR → owner/id；状态为 disabled/registering/registered/failed，携带错误、尝试次数、注册/过期/重试时间。
2. Manager 提供 List/Create/Update/Delete 与 AOR lookup。每个 enabled credential 一个独立后台 worker 和 SIP UA/socket；编辑与 enable 变化重建 worker，disable/delete 先撤销 AOR 路由并 de-REGISTER。替换同一 entry 时等待旧 worker 退出再启动新 worker，避免旧 wildcard unregister 删除新绑定。
3. worker 串行执行带超时的 REGISTER、按授予 expiry 的刷新、失败 capped backoff + jitter 重试；停止时用独立短 context 注销，再关闭 UA。API 返回表示保存成功，实际注册异步推进，轮询可见状态。
4. 新增 `pkg/api/sipcredentials`：`GET/POST /api/sip/credentials`、`PUT/DELETE /api/sip/credentials/{id}`。请求只含 server/username/password/transport/enabled；响应永不包含 password，PUT 空密码表示保留。全部按 JWT subject 隔离，外部不可设置注册状态。
5. 真实 SIP adapter 支持 udp/tcp/tls/ws，绑定路由源地址和临时端口；入站 INVITE/MESSAGE 通过统一 AOR 索引查 owner。未匹配记录结构化日志并回 404；已匹配但本期无呼叫/消息实现时记录并回 480/501，不创建浏览器直连或伪造已分发。
6. 新增 `docs/user-sip-subsystem.md`：记录控制/信令边界、状态机、重试与资源生命周期、AOR/CAM 路由目标、未来多 UA 振铃、无转码 RTP 安全代理与能力透传原则、当前限制和后续决策。
7. 前端新增 SIP credential React Query API/hook，设置页轮询服务端列表；支持添加、编辑、删除、enabled 开关和逐项状态/错误/重试显示，移除 placeholder 与本地权威列表，不写 SIP localStorage。
8. 测试：AOR 解析与隔离、Manager 生命周期/旧 worker 防写、重试与关闭、HTTP 认证/CRUD/密码不外泄；diago expiry patch；真实 loopback UDP REGISTER/认证/刷新/注销与 unmatched 入站。随后运行聚焦及全量 Go（含 race 的可行范围）、Vitest、ESLint、TypeScript、Next build。
9. 启动 Go 8080 与 Next `localhost:3000`，实际用浏览器验证两个访客的数据隔离、CRUD、开关、服务端状态和响应式 UI；开发记录回写实际结果、偏差与剩余风险，不提交不部署。

# 审查记录与计划修正

第一轮独立审查（仅读）发现了顺序测试未覆盖的问题，执行计划追加以下修正后再验收：

- Delete 移除 AOR 后、旧 unregister 尚未结束时可重建同 AOR；Update 在停止旧 worker 期间目标 AOR 可被抢占。采用按 AOR 哈希分桶的生命周期锁（旧/新 AOR 按序加锁），覆盖注销等待窗口，避免 tombstone 泄漏和全局网络锁。
- diago 通配 `Contact: *` 注销会删除同 AOR 其他设备的 binding；改为仅对当前 Contact 设置 `expires=0`。AOR 生命周期锁仍保留，以维护索引唯一性与替换顺序。
- expiry 必须从本 UA 对应的 Contact 读取，参数名大小写不敏感，且解析失败不得清零旧租期。需要兼容多 Contact 响应；先验证 sipgo 实际解析能力再决定最小 patch。
- 省略 enabled 的 API 保留语义需移入 Manager 的串行更新边界；前端编辑快照和 mutation reset/pending 需修正。
- visitor 默认可创建无限 egress/socket 的风险需要限额与目标约束；敏感写请求补同源 Origin 与 JSON Content-Type 防护。
- URI 解析错误与端口范围需同步验证。
- 初次 200 后 expiry 解析失败的远端 binding 清理、malformed 后恢复、确定性并发回归纳入测试。
