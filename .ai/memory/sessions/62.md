# Request and scope

Implement the backend user-SIP wire model and WebSocket delivery slice. Production
and test changes are limited to `pkg/models/ss/ss.go`,
`pkg/models/ss/*test.go`, `pkg/api/websocket_ss/websocket_ss.go`, and
`pkg/api/websocket_ss/*test.go`. Add SIP call/MESSAGE payloads to both SS event
directions, intercept client SIP events ahead of the ordinary provider, and
provide hub-mediated subject fan-out and exact-delivery sends. Run the focused
Go tests with the race detector.

# Status

Complete — the scoped wire model and WebSocket fan-out are implemented and the
focused race-enabled tests pass.

# Investigation

Verified from the current implementation and tests:

- `ss.SignallingEvent` already carries Pion SDP/ICE types elsewhere, and the SS
  provider contract is message-only. The new SIP service UUID does not require a
  new dependency.
- `WebSocketSSHandler` has one hub goroutine owning `conns` and the CAM table.
  Every upgraded socket is registered before its pumps start, even without an
  SS channel registration. Each socket has a bounded queue; ordinary provider
  delivery is nonblocking and drops a slow connection.
- `wsConn.camKey` contains the authenticated user/session identity. A generated
  opaque delivery ID can therefore support subject scans across sessions and
  exact current-socket sends without exposing CAM internals or adding SIP work
  to connection goroutines.
- Existing `From` stamping replaces user/session but leaves `ServiceId`; the
  intercepted SIP path must explicitly replace the whole source address so a
  spoofed service ID cannot survive. Non-SIP provider forwarding should remain
  untouched.
- A callback invoked directly by the hub is appropriate only under the required
  contract that it enqueues service work and returns quickly. Fan-out and send
  requests must use the bounded ingress channel, caller-context cancellation,
  and capacity-one acknowledgements so hub completion never depends on an
  abandoned caller.

# Plan

1. Add `WellKnownSvcIdSIP`, `SIPCallEvent`, and `SIPMessageEvent` with the
   specified JSON names and Pion payload types. Add `sipCall` and `sipMessage`
   to both client/server event bodies. Use the existing Go `Id`/`Uri` naming
   style without changing wire names; make IDs required in JSON and other SIP
   fields optional.
2. Add an exported SIP callback interface and pre-serving setter. Generate one
   UUID delivery ID per upgraded `wsConn`. In the hub, intercept either SIP c2s
   payload, stamp the full authenticated `From`, invoke the callback without
   forwarding to the ordinary provider, and notify disconnect only after the
   socket has been removed. Cover overflow and hub shutdown as well as read
   closure.
3. Implement `FanoutSIP` and `SendSIP` through context-aware hub notes and
   buffered acks. Reject calls with zero or two payloads. For each delivery,
   construct a separate envelope/body/payload copy with a fresh message ID,
   complete user/session `To`, and SIP service `From`. Preserve nonblocking
   queues: return only successful delivery IDs, return false for missing/stale/
   full targeted delivery, and drop only a slow socket. No matching sockets is
   a successful empty fan-out.
4. Add wire-shape tests and hub/integration tests for multiple sessions and
   duplicate sockets, user isolation, no-channel-registration delivery, unique
   envelopes/IDs, exact/stale sends, overflow, spoof clearing/provider bypass,
   disconnect notification, invalid payloads, and cancellation-safe operation.
5. Run `gofmt` on changed Go files, then `go test -race ./pkg/api/websocket_ss
./pkg/models/ss`. Record exact results and remaining blind spots below.

# Outcome

Implemented the requested backend SIP delivery slice with no wire-field name
changes:

- `pkg/models/ss/ss.go` adds the exact SIP service UUID, call/MESSAGE event
  structs, Pion SDP/ICE payloads, optional-field JSON behavior, and `sipCall` /
  `sipMessage` in both c2s and s2c bodies. `callId` and `messageId` remain
  required; the other fields, including `createdAt`, are optional.
- `pkg/api/websocket_ss/websocket_ss.go` adds `SIPHandler`,
  `SetSIPHandler`, per-upgrade UUID delivery IDs, authenticated SIP
  interception, and disconnect callbacks after socket removal. `FanoutSIP` and
  `SendSIP` use bounded ingress notes, caller-context cancellation, and
  capacity-one acks. Each accepted delivery receives a distinct envelope/body/
  outer-payload copy and message ID, a complete user/session `To`, and a SIP
  service-only `From`. Full queues drop only the affected socket. Ordinary
  provider forwarding remains on its previous path.
- `pkg/models/ss/sip_test.go` checks both envelope directions, every JSON field,
  required/optional fields, SDP/ICE shape, timestamps, and the service UUID.
- `pkg/api/websocket_ss/sip_test.go` and the small test-harness extension in
  `websocket_ss_test.go` cover fan-out across sessions and duplicate sockets,
  user exclusion, independent copies and message IDs, no-connection success,
  delivery before SS channel registration, exact/stale/targeted sends, full
  queues, generated delivery IDs, spoofed source replacement, provider bypass,
  ordinary-provider preservation, disconnects, invalid payloads, and canceled
  contexts.

Validation:

- Initial `gofmt ... && go test ./pkg/models/ss ./pkg/api/websocket_ss` found a
  duplicate test-only Gorilla import; `pkg/models/ss` passed and
  `pkg/api/websocket_ss` did not compile. The duplicate import was removed.
- `gofmt -w pkg/api/websocket_ss/sip_test.go && go test
./pkg/api/websocket_ss` passed.
- `go test -race ./pkg/api/websocket_ss ./pkg/models/ss` passed.
- After the final documentation and UUID-assertion edits, `gofmt -w
pkg/models/ss/sip_test.go pkg/api/websocket_ss/websocket_ss.go && go test
-race ./pkg/api/websocket_ss ./pkg/models/ss` passed:
  `ok personal-site/pkg/api/websocket_ss 2.091s` and
  `ok personal-site/pkg/models/ss 4.009s`.
- Zed diagnostics reported no errors or warnings for either production file.

Remaining blind spots: these are focused model/hub/WebSocket tests; no live
external SIP registrar, RTP/media path, or end-to-end `sipregistration.Service`
integration was exercised because those are outside this file-limited slice.
Unrelated pre-existing workspace changes were not modified.
