## Request and scope

Implement package-private browser/SIP negotiation, Pion browser media, diago SIP media setup, and bidirectional no-transcode RTP relay for `pkg/sipregistration`. Production changes are restricted by the request to `sdp.go` and new `media.go`; tests are restricted to `sdp_test.go` and new `media_test.go`. Do not modify service, manager, runtime, inbound, command, frontend, or docs code.

## Status

Complete: browser/SIP negotiation, diago media setup, Pion answerer, no-transcode relay, and focused tests are implemented and race-validated.

## Verified findings and design corrections

- Baseline `go test -race ./pkg/sipregistration` passed.
- diago `AudioReader` defaults to encoded RTP through `RTPPacketReader`; no decoder is inserted unless an option adds one. Its `PacketHeader` is valid immediately after each read.
- diago models one RTP/RTCP transport. A shared audio/video read must therefore be demuxed in one goroutine rather than racing two reads. The selected video codec must also remain in `MediaSession.Codecs`, or diago drops it as an unsupported payload during RTP statistics handling.
- `RTPPacketWriter.WriteSamples` accepts explicit timestamp deltas, marker, and PT. Its constructor requires a positive sample duration, but `ClockDisable` stops that clock immediately; the relay will pass actual packet deltas and will not pace packets.
- A distinct SIP video destination needs only a dedicated connected UDP writer: both SDP offers initially advertise the shared local RTP port, so inbound video still arrives on the diago reader. The dedicated socket will be owned and closed by the relay.
- Pion `TrackRemote.ReadRTP` returns `(packet, attributes, error)`. A custom empty `MediaEngine`, explicit selected-codec registration, default interceptor registry, and `SetAnsweringDTLSRole(DTLSRoleClient)` provide the required answerer without default codec injection.
- `DialogMedia.InitMediaSession` injects packet readers/writers but does not populate diago's private RTP-session pointer. The inbound constructor returns the RTP session and registers close monitoring; the relay supports a nil `dialog.RTPSession()` by writing through `MediaSession`.

### Intermediate findings and corrections

- The first relay fixture reused an RTP sequence number; SRTP replay protection correctly dropped the second packet. The fixture was corrected to use distinct sequence numbers.
- The first timestamp implementation passed each delta as `WriteSamples`' increment. Diago emits the old timestamp before applying that increment, so the second packet lagged by one delta. The final writer applies the delta with `DelayTimestamp` before zero-increment `WriteSamples`; tests now observe exact original timestamps.
- Review added an independent plaintext parse inside inbound setup, case-insensitive codec-name checks, and early rejection of equal selected audio/video PTs on diago's shared RTP socket.

### Limits and integration notes

- The relay supports one audio and one optional video m-line, with distinct selected SIP PTs on the shared local RTP socket. Repair, redundancy, comfort-noise, and telephone-event payloads are not negotiated or relayed.
- A different SIP video destination uses a dedicated connected UDP RTP writer. Incoming video still arrives on the originally advertised shared local port. There is no separate SIP video RTCP relay.
- RTP payloads, selected PT mapping, timestamps, and markers are preserved; sequence numbers and SSRCs are leg-local. Browser-to-SIP header extensions/CSRC/padding are not preserved by diago's payload writer.
- Tests use local Pion peers and host ICE/DTLS, not a physical browser, STUN/TURN, NAT, or loss/reordering simulation.
- diago `InitMediaSession` does not set its private inbound RTP-session pointer. The constructor returns that session explicitly; `mediaRelay` accepts a nil interface `RTPSession()` by writing through `MediaSession`, or a future service wrapper can expose the returned pointer.
