## Request and scope

Fix review issues 3, 5, and 6 in `pkg/sipregistration/service.go` and `service_test.go`: preserve per-delivery control ordering without blocking hub delivery or long network operations; reject invalid inbound accept legs without consuming the winner and terminate only when no usable legs remain; distinguish pre-answer failure cleanup from post-answer BYE cleanup, including robust final-2xx dialog-plus-error handling. Other runtime/diago/frontend/websocket/media files are owned by other agents and must not be changed.

## Findings

- `run` currently starts an independent goroutine for every queued event, so a later ICE/disconnect can run before the dial has inserted its call.
- `runOutbound`, `runInboundAccept`, and `runtime.SendMessage` can block for network/dialog durations. Diago sets a client dialog to `Confirmed` in `WriteAck` and to `Ended` after BYE; its media-error path may already have ACKed/BYEd before returning a dialog and error.
- Invalid inbound accepts currently return without changing the leg or notifying its UI. Accept media setup failures request 488, but `waitInbound` unconditionally calls `Hangup`, which produces 480 before confirmation. A successful `Answer` followed by an immediate hangup can leave `accepted == false`, so a separate answer-success flag is required.

## Plan

1. Replace independent event goroutines with one bounded FIFO control loop. Keep a bounded nonblocking operation-slot pool for long-running outbound, inbound-answer, and MESSAGE goroutines. Never close work/slot channels; cancellation ends the control loop and all per-call/message contexts.
2. Insert outbound state and launch its INVITE/ACK/dialog wait asynchronously before processing the next control event. Reserve an answer operation before committing an inbound winner; run media setup and `Answer` off the control loop. Keep message ID validation/registration ordered, but perform SIP MESSAGE I/O and result delivery asynchronously.
3. Add a helper that marks an invalid inbound accept leg terminal, sends that leg a concise rejected event, and requests call termination with 488 for malformed/no-common-media (403 for egress policy) only when no usable legs remain. Do not set or clear another leg's winner.
4. Record `answered` only when inbound `Answer` returns nil. On cancellation, wait for pre-ACK answer completion as before; use BYE/Hangup only after `answered`, otherwise send the requested final response (488 for media setup failure, defaulting to 480).
5. Make outbound final cleanup ACK an unACKed final-2xx dialog and then BYE, including dialog-plus-error returns. The Diago wrapper will treat `Confirmed`/`Ended` as already ACKed and expose whether the final response was 2xx, preventing duplicate ACKs and avoiding ACK for non-2xx dialogs.
6. Add deterministic immediate dial+ICE and dial+disconnect tests without waiting for INVITE before sending control; sole-invalid and invalid-then-valid accept tests; pre-answer 488 versus post-answer BYE tests; and outbound dialog-plus-error ACK/BYE plus already-ACKed coverage.
7. Run `gofmt` only on the two requested Go files, then `go test -race ./pkg/sipregistration`. Record exact outcomes and any remaining risks.

## Outcome

Complete. Changed only the requested service implementation/tests for this task:

- `pkg/sipregistration/service.go`: a single bounded FIFO control loop now preserves event/disconnect order. A 64-slot nonblocking operation pool carries outbound INVITE/ACK/dialog waits, inbound media/Answer work, and outbound MESSAGE I/O off that loop. Work and slot channels are never closed.
- Invalid inbound accepts mark only their own leg terminal and emit a concise `rejected` event. Negotiation failures use 488 and egress-policy failures use 403 when the last usable leg fails; other legs remain eligible.
- Inbound `answered` tracks a nil `Answer` result independently of UI `accepted`. Pre-answer cleanup sends the requested final response; successful pre-ACK/post-ACK answers use Hangup/BYE after the existing answer wait.
- Outbound cleanup can independently ACK then BYE a final-2xx dialog returned with an error. Diago dialog state suppresses a duplicate ACK when already `Confirmed` or `Ended`; non-2xx dialogs are only closed.
- `pkg/sipregistration/service_test.go`: added immediate dial+ICE and dial+disconnect regressions, dialog-plus-error ACK/BYE and already-ACKed tests, sole-invalid and invalid-then-valid accept tests, and explicit pre-answer 488 versus post-answer BYE coverage. Kept the original first-valid-accept loser-cancellation coverage by separating it from invalid-accept coverage.
