## Request and scope

Fix frontend review issues 2, 10, and 12. Production and test changes are limited to `web/site/src/api/ss/sip.ts`, `sip.test.ts`, `web/site/src/components/chat/sipForm.ts`, and `sipForm.test.ts`; do not change backend or other frontend source files. Validate with focused Vitest runs, `npx tsc --noEmit --incremental false`, and `npm run lint` in `web/site`.

## Status

In progress. Investigation is complete enough to implement the plan; no source changes have been made yet.

## Verified findings

- `failCall` currently marks a call failed and cleans up without a SIP control event. Direct media/connection paths send `hangup` separately, while offer-candidate and server-description/candidate failures can strand the server dialog.
- `offerSent` becomes true only after the initial dial/accept write succeeds. It is the required gate for failure notifications: pre-offer setup and initial-offer write failures must clean up locally without CANCEL/DECLINE/BYE.
- The hook creates each replacement `ExternalSIPClient` without `iceServers`; its ICE-update effect does not rerun when the URL array is unchanged across a proxy reconnect. The existing `react.test.tsx` provides a dependency-free hook runtime pattern suitable for a regression test.
- `Credential.registration` already exposes optional `expires_at` and `registered_at`. Eligibility currently requires `state === "registered"`, dropping a selected caller during registering/failed refresh even if its lease remains valid.

## Plan

1. Centralize idempotent best-effort failure aborts. Mark failure synchronously to exclude duplicate local failures, choose incoming pre-accept `decline`, outgoing pre-accept `cancel`, or post-accept `hangup`, send only after `offerSent`, swallow abort-write failures, and clean up only after the notification attempt settles. Route negotiation, candidate, media, and connection failures through it; avoid a second abort after a user control write itself was already attempted.
2. Keep a current ICE-server ref and pass its value to every client constructor while retaining the existing update effect for URL changes on a live client. Add a hook-level reconnect regression with an unchanged URL array and assert both incarnations construct peer connections with STUN/TURN.
3. Make eligibility require enabled plus a parseable, strictly future `expires_at`, independent of registered/registering/failed state; never infer a lease from `registered_at`. Add refresh-state, missing/invalid/exact-boundary/expired lease, and selection-reconciliation tests using an explicit `now` parameter.
4. Run the two focused test files, typecheck, and lint. Record exact outcomes and any remaining blind spots below.

## Outcome

Complete. Source changes are limited to the four requested frontend files; `useSipCredentials` types did not need changes.

- `sip.ts` now routes negotiation, trickled/pending ICE, media acquisition, and connection failures through a centralized best-effort abort. A successfully written dial/accept offer is required before any abort; incoming pre-accept failures use `decline`, outgoing dialing/ringing failures use `cancel`, and accepted failures use `hangup`. Failure state is marked synchronously to deduplicate concurrent failures, abort writes are caught, cleanup waits for the abort attempt, and terminal-state ICE guards prevent further candidate sends during cleanup. A failed user control write is treated as the already-attempted abort rather than duplicated.
- The hook updates a current-ICE ref in an effect ordered before client creation and passes that value to every `ExternalSIPClient` constructor. The same effect retains live-client ICE updates without recreating clients for URL changes.
- `sipForm.ts` now requires enabled plus parseable `expires_at > now`, regardless of registered/registering/failed refresh state. Missing, invalid, exact-boundary, and expired leases are excluded; `registered_at` is not consulted.
- Tests cover pre-offer create/set-local/initial-write failures, outgoing and incoming ICE-send failures, duplicate suppression, abort-write rejection, cleanup ordering, remote SDP/ICE failures, accepted media failure, direction/state action selection, unchanged-URL proxy reconnects, refresh-state eligibility, expiry boundaries, and selection reconciliation.

Intermediate corrections:

- The first test run exposed a misplaced closing delimiter in a new test; it was corrected.
- Two concurrent ICE tests initially inspected state before the existing 15-microtask drain reached cleanup. Increasing the deterministic drain to 50 microtasks fixed the test synchronization; the subsequent run passed without a production change.
- Lint rejected a render-time ref write and direct hook invocation in the test runtime. The ref update moved into the ordered ICE effect, and the deliberate test-only hook call received a narrow rule suppression.
- Final review added terminal-state guards to stop ICE queueing/sending between local failure publication and abort completion.

Final validation in `web/site`:

- `npm test -- src/api/ss/sip.test.ts src/components/chat/sipForm.test.ts` — passed, 2 files and 22 tests.
- `npx tsc --noEmit --incremental false` — passed.
- `npm run lint` — passed.

Remaining blind spots: tests use mocked browser peer connections/media and transports plus the repository's lightweight hook runtime; no physical browser STUN/TURN allocation or live external SIP dialog was exercised. Broader frontend tests were not requested or run.
