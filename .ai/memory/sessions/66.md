## Request and scope

Fix frontend review issues 2, 10, and 12. Production and test changes are limited to `web/site/src/api/ss/sip.ts`, `sip.test.ts`, `web/site/src/components/chat/sipForm.ts`, and `sipForm.test.ts`; do not change backend or other frontend source files. Validate with focused Vitest runs, `npx tsc --noEmit --incremental false`, and `npm run lint` in `web/site`.

## Status

In progress. Investigation is complete enough to implement the plan; no source changes have been made yet.

## Verified findings

- `failCall` currently marks a call failed and cleans up without a SIP control event. Direct media/connection paths send `hangup` separately, while offer-candidate and server-description/candidate failures can strand the server dialog.
- `offerSent` becomes true only after the initial dial/accept write succeeds. It is the required gate for failure notifications: pre-offer setup and initial-offer write failures must clean up locally without CANCEL/DECLINE/BYE.
- The hook creates each replacement `ExternalSIPClient` without `iceServers`; its ICE-update effect does not rerun when the URL array is unchanged across a proxy reconnect. The existing `react.test.tsx` provides a dependency-free hook runtime pattern suitable for a regression test.
- `Credential.registration` already exposes optional `expires_at` and `registered_at`. Eligibility currently requires `state === "registered"`, dropping a selected caller during registering/failed refresh even if its lease remains valid.

## Plan

1. Centralize idempotent best-effort failure aborts. Mark failure synchronously to exclude duplicate local failures, choose incoming pre-accept `decline`, outgoing pre-accept `cancel`, or post-accept `hangup`, send only after `offerSent`, swallow abort-write failures, and clean up only after the notification attempt settles. Route negotiation, candidate, media, and connection failures through it; avoid a second abort after a user control write itself was already attempted.
2. Keep a current ICE-server ref and pass its value to every client constructor while retaining the existing update effect for URL changes on a live client. Add a hook-level reconnect regression with an unchanged URL array and assert both incarnations construct peer connections with STUN/TURN.
3. Make eligibility require enabled plus a parseable, strictly future `expires_at`, independent of registered/registering/failed state; never infer a lease from `registered_at`. Add refresh-state, missing/invalid/exact-boundary/expired lease, and selection-reconciliation tests using an explicit `now` parameter.
4. Run the two focused test files, typecheck, and lint. Record exact outcomes and any remaining blind spots below.

## Outcome

Complete. Source changes are limited to the four requested frontend files; `useSipCredentials` types did not need changes.

- `sip.ts` now routes negotiation, trickled/pending ICE, media acquisition, and connection failures through a centralized best-effort abort. A successfully written dial/accept offer is required before any abort; incoming pre-accept failures use `decline`, outgoing dialing/ringing failures use `cancel`, and accepted failures use `hangup`. Failure state is marked synchronously to deduplicate concurrent failures, abort writes are caught, cleanup waits for the abort attempt, and terminal-state ICE guards prevent further candidate sends during cleanup. A failed user control write is treated as the already-attempted abort rather than duplicated.
- The hook updates a current-ICE ref in an effect ordered before client creation and passes that value to every `ExternalSIPClient` constructor. The same effect retains live-client ICE updates without recreating clients for URL changes.
- `sipForm.ts` now requires enabled plus parseable `expires_at > now`, regardless of registered/registering/failed refresh state. Missing, invalid, exact-boundary, and expired leases are excluded; `registered_at` is not consulted.
- Tests cover pre-offer create/set-local/initial-write failures, outgoing and incoming ICE-send failures, duplicate suppression, abort-write rejection, cleanup ordering, remote SDP/ICE failures, accepted media failure, direction/state action selection, unchanged-URL proxy reconnects, refresh-state eligibility, expiry boundaries, and selection reconciliation.

Intermediate corrections:

- Lint rejected a render-time ref write and direct hook invocation in the test runtime. The ref update moved into the ordered ICE effect, and the deliberate test-only hook call received a narrow rule suppression.
- Final review added terminal-state guards to stop ICE queueing/sending between local failure publication and abort completion.

## Continuation: SIP MESSAGE chat integration audit

### Request and status

In progress. Audit what the previous implementation omitted, then implement the missing behavior. Reuse the existing chat interface. Confirming an outgoing dial opens chat immediately (before the peer answers); incoming ringing must not change the current pane, and only the user's accept action opens that chat. A contact's chat action also opens chat. The chat shows SIP MESSAGE history/composer, call FFT, and video when present. Verify these paths in a running UI rather than inferring success only from source.

### Audit checklist

- Trace outgoing dial confirmation, incoming ringing versus explicit acceptance, and contact chat navigation to the existing conversation UI.
- Trace real SIP MESSAGE send and receive behavior, including conversation/peer identity, delivery failures, and history integration.
- Check spectrum/video coexistence with the message UI and add focused regression coverage for omissions.
- Record verified findings and the implementation/test plan here before editing production code.

### Verified omissions

- SIP MESSAGE transport/reducers already exist, but `PhonePanel` only exposes a flat history and separate reply dialog rather than a per-peer chat.
- `ExternalSIPCallOverlay` never opens a conversation on dial or accept and has no FFT panel.
- `PhoneContactView` explicitly labels its actions as scaffolding; chat only shows an unavailable notice.
- Internal incoming-call acceptance likewise does not select the call's conversation if another pane is open.

### Corrected plan

1. Add a per-credential/per-target external conversation model and a right-hand chat pane composed from the existing message history, composer, call panel, spectra, and video windows. Show SIP MESSAGE delivery state/reason and omit unsupported attachments.
2. On dial confirmation, call `sip.dial` and immediately open the new call's conversation. Do not use call-progress events for outgoing navigation.
3. On incoming ringing, show only the existing call popup. On the user's accept click, open the conversation and call `sip.accept`; never auto-navigate from incoming events.
4. Open external history items in their conversation; wire internal contact voice/video/chat actions and select internal conversations on incoming acceptance.
5. Add focused model tests, run Vitest/TypeScript/lint, then exercise the three navigation paths and SIP MESSAGE send/receive in a real browser using the existing loopback PBX setup.

### Correction log

- An initial, unintegrated draft incorrectly waited for outgoing `accepted`; it was rejected and removed. Outgoing navigation belongs synchronously in the dial-confirmation action. Incoming navigation belongs only in the explicit accept action.
- The first implementation retained separate Calls/Messages tabs, an active-call floating card, a custom SIP chat header, and custom incoming-call chrome. These were removed. External SIP now renders the same `ConversationView` and `IncomingCallWindow`; the former overlay only mounts video streams.
- Call history uses the existing `UserAvatar`, shared row styling, and the extracted existing `CallStatusPill`; it no longer shows a redundant direction label beside live-call state. Current external conversation selection is reflected on its latest history row.
- External calls produce one `PhoneCallItem` per `callId`, folded into the same timeline as SIP MESSAGEs and updated from inviting to accepted/terminal states. Added `failed` rendering without changing internal call states.
- Raw target `2002` and canonical `sip:2002@host` are compared using the event's local account URI. This was caught by a real incoming MESSAGE not appearing in the raw-target chat, then fixed and covered by tests.
- Review found and fixed MESSAGE-only peer discovery, composer draft isolation by conversation, call-timer isolation by `callId`, and newest-first arbitration when internal/external calls ring simultaneously.
- Internal `select` toggles an already-selected conversation, so accept/contact actions now use an ensure-open path instead of accidentally deselecting it.
- External history timestamps/order use INVITE `since`, not status-update `updatedAt`.
- A real screenshot exposed selected-row overflow. Measured DOM widths showed PhonePanel's flex item at 349px inside a 319px content area because it lacked `minWidth: 0`; adding it reduced the row to 319px and nav scrollWidth to clientWidth.

### Final outcome

Complete for the requested SIP chat/call integration.

- `PhonePanel.tsx` is one call/live-contact list with no inner tabs. Dial confirmation immediately opens chat. External MESSAGE-only peers are discoverable, history rows open chat, and the selected row is highlighted without horizontal overflow.
- `ExternalSIPConversationView.tsx` is only a data adapter over the ordinary `ConversationView`. SIP MESSAGE sending/receiving, delivery state/reason, per-call status messages, FFT, and video share the existing chat components.
- `ChatApp.tsx` implements immediate outgoing navigation, explicit-accept-only incoming navigation, ensure-open internal accept/contact behavior, and shared incoming-call presentation. `PhoneContactView.tsx` voice/video/chat actions are functional.
- Shared `CallStatusPill.tsx`, `ConversationView.tsx`, `CallPanel.tsx`, `MessageList`/`MessageItem`, `MessageInput.tsx`, and `IncomingCallWindow.tsx` provide the common UI. `ExternalSIPCallOverlay.tsx` no longer contains call cards or a separate incoming popup.
