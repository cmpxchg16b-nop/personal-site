## Request and scope

After private/loopback registrar support was committed as `c97fe89`, registration to the user's LAN SIP server `192.168.1.224` succeeded but calls failed. Investigate and fix the actual outbound and inbound SIP call failures, validate them with focused and broader tests, restart the local backend, and record the outcome here.

## Status

Live retest advanced past the original failures but exposed a post-answer 488. Redirect and rewritten-To routing are confirmed live; investigation is now focused on the inbound media/answer path.

## Verified findings

- Live credential: `sip:1002@192.168.1.224`, UDP, state `registered` with a valid lease.
- Live outbound failures include `outbound SIP INVITE failed ... err="Invite failed with response: SIP/2.0 302 Moved Temporarily"`; the current `diagoRuntime.Invite` treats every non-2xx final response as terminal and never follows the redirect Contact.
- Live inbound INVITEs from `192.168.1.224:5060` arrive with To/Request-URI hosts rewritten to the UA's local contact host, e.g. `sip:1002@192.168.10.201` and `sip:1003@192.168.10.201`. `resolveInbound` looks up the complete configured AOR (`user@192.168.1.224`), so these requests incorrectly return 404. A second full-AOR comparison in the runtime handler would reject them even after changing lookup alone.
- Each listener callback already carries its exact `diagoRuntime` pointer. That runtime identifies one credential generation, so matching runtime plus SIP username preserves account isolation while tolerating Contact-host rewriting.
- Redirect attempts must reuse the same SDP and media socket. Calling the outer `dialog.Close()` between attempts would close that socket; only the failed SIP leg should be closed before creating the redirected dialog.

## Plan

1. Follow SIP 300/301/302 Contact targets with a bounded loop and loop detection. Validate the Contact using the existing SIP target rules, route the new INVITE to the Contact host/port, retain provisional-progress forwarding, and close media exactly once on terminal failure.
2. Resolve runtime inbound INVITE/MESSAGE by exact current runtime plus To username rather than complete rewritten AOR. Preserve enabled, generation, and lease checks.
3. Add a real UDP redirect test (302 Contact -> second INVITE -> 200) covering destination, media reuse, and loop/failure behavior where practical. Add inbound rewritten-To coverage proving the request reaches the existing service instead of returning 404, while a wrong username still fails.
4. Run focused tests, the full `pkg/sipregistration` and API tests, race checks where appropriate, build, and frontend checks only if frontend files change. Rebuild the local backend. A restart requires explicit confirmation because the in-memory credential store cannot preserve the user's account across it; verify through the live LAN PBX after restart and re-registration.
5. Record corrections, exact validation outcomes, remaining blind spots, and final status below.

## Intermediate findings and corrections

- The existing integration test `TestDiagoRuntimeRegisterRefreshRouteAndUnregister` expects the log phrase `inbound SIP signaling resolved to user`. The first runtime-resolution edit changed it to `resolved to runtime`, causing only that log assertion to fail. Preserve the established phrase rather than changing an unrelated test expectation.
- No session note was created for the earlier tightly scoped private-IP validation change; the user has explicitly requested a note for this larger call-routing change.
- The first redirect test still returned the original 302 because Diago returned `*sipgo.ErrDialogResponse` while the code extracted only a value error. The implementation now accepts both pointer and value forms.
- `ServeBackground` listener startup is asynchronous; the new test initially raced `ListenPorts` and was corrected to wait for both UDP listeners.
- The redirected INVITE increments the SDP origin version. The test initially demanded byte-identical SDP and was corrected to assert the required invariants instead: same media IP/port and codecs. This was a test correction, not a production workaround.
- Final review preserved legacy non-3xx error text and added a nil-media guard to the redirect-only SIP-leg cleanup path.
