# Request

用户指出 `/chat` 设置的 Devices 页面显示不存在的 “Microphone 1”，而其他网页能显示真实麦克风名称。要求查明并修复，而不是用文案掩盖。

# Scope and status

Status: in progress. 范围限定为设备设置初始化时的媒体设备枚举和标签获取，保留用户已有的 `README.md`、`web/site/next.config.ts` 修改。

# Verified findings

- `DeviceSelect` 在 `MediaDeviceInfo.label` 为空时使用 `chat.devices.unnamed`（`"{{kind}} {{index}}"`），所以 “Microphone 1” 是前端占位名，不是浏览器返回的真实设备名。
- `refreshDevices` 当前直接调用 `enumerateDevices()`。
- 页面初始化会自动 `startCamera()`，摄像头采集成功后刷新列表；麦克风只有用户点击 Test 后才 `acquireLocalInput()` 并刷新列表。因此首次打开页面时，浏览器可在麦克风权限尚未授予时隐藏其标签。

# Plan

1. 将设备枚举抽成可测试的小helper：先普通枚举；若存在无标签的音频输入，则短暂申请 `{ audio: true }`，在采集有效期间重新枚举以获取真实标签，随后立即停止该临时采集的全部 tracks。
2. 权限拒绝或采集失败不阻断普通设备列表，也不覆盖已有的设备设置错误；已有有效标签时不额外申请权限，避免重复提示和采集。
3. 添加 focused tests，覆盖无标签时刷新、临时 track 释放、权限拒绝回退、已有标签不额外采集，以及枚举本身失败时不申请采集。
4. 运行 focused tests、相关媒体测试、lint 和 TypeScript 检查；如可进行浏览器验证，确认选择框展示真实设备名且临时采集已停止。
